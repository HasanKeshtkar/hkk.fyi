# سیستم نوبت‌دهی مطب

اپ موبایل (PWA) نوبت‌دهی برای دو کاربر: دکتر و منشی. روی **Cloudflare** (پلن رایگان) اجرا می‌شود: یک Worker برای صفحه‌ها و یک Durable Object که همه داده‌ها (SQLite)، API و کانال لحظه‌ای را نگه می‌دارد.

> این پوشه را در شاخه `main` مخزن hkk.fyi ادغام نکنید: Cloudflare Pages سایت را از `main` منتشر می‌کند.

## نصب روی گوشی (دکتر و منشی)
1. در **کروم** اندروید `https://clinic.hkk.fyi` را باز کنید و وارد شوید.
2. «ساعت کاری» (آیکن چرخ‌دنده) ← «نصب روی گوشی» ← «نصب برنامه روی صفحه اصلی».
   اگر دکمه نبود: منوی ⋮ کروم ← «نصب برنامه» یا «افزودن به صفحه اصلی».
3. از این به بعد برنامه را با آیکن دندان باز کنید. ورود تا ۱۸۰ روز (با هر بار استفاده تمدید) می‌ماند.

صدای اعلان بعد از اولین لمس صفحه فعال می‌شود (محدودیت مرورگر). وقتی برنامه بسته است اعلانی نمی‌رسد.

## راه‌اندازی (یک بار، فقط با مرورگر)
1. **توکن Cloudflare:** dash.cloudflare.com/profile/api-tokens ← Create Token ← قالب «Edit Cloudflare Workers» ← دو مجوز اضافه: `Zone / Zone / Read` و `Zone / DNS / Edit` ← Zone Resources: `hkk.fyi` ← Create Token.
2. **GitHub:** مخزن ← Settings ← Secrets and variables ← Actions ← New repository secret، سه تا:
   - `CLOUDFLARE_API_TOKEN` = توکن مرحله ۱
   - `SEED_DOCTOR_PASSWORD` = رمز دکتر (حداقل ۸ کاراکتر)
   - `SEED_SECRETARY_PASSWORD` = رمز منشی (حداقل ۸ کاراکتر)
3. همین. هر push به این شاخه (`ccr-be786f2b-2eug68`؛ شاخه‌های دیگر فقط تست می‌شوند) که همه تست‌ها را رد کند، خودکار روی Cloudflare مستقر می‌شود (کار `deploy` در Actions). اگر در این فاصله push جدیدتری آمده باشد، نسخه قدیمی‌تر مستقر نمی‌شود. Cloudflare دامنه `clinic.hkk.fyi` و گواهی SSL را خودش می‌سازد؛ دو کاربر در اولین اجرا ساخته می‌شوند.

نام‌ها و دامنه در `wrangler.jsonc` (بخش `vars` و `routes`) هستند.

### تغییر رمز (مثلاً گوشی گم شده)
رمز جدید (حداقل ۸ کاراکتر) را در همان secret در GitHub بگذارید و **آخرین** اجرای Actions را دوباره اجرا کنید (Re-run all jobs). رمز قبلی از کار می‌افتد و همه دستگاه‌های **همان نفر** از حساب خارج می‌شوند؛ نفر دیگر دست نمی‌خورد. رمز کوتاه‌تر یا چندخطی، اجرا را با خطا متوقف می‌کند (چیزی عوض نمی‌شود).

### انتقال به دامنه ‎.ir
1. اگر DNS دامنه ‎.ir روی Cloudflare است: در `wrangler.jsonc` دامنه جدید را به `routes` اضافه کنید و `APP_ORIGIN` را `https://clinic.example.ir,https://clinic.hkk.fyi` کنید (جدید اول). push.
2. روی هر دو گوشی: آدرس جدید را باز کنید، دوباره وارد شوید و برنامه را دوباره نصب کنید. (ورود و برنامه نصب‌شده به آدرس وابسته‌اند.)
3. بعد دامنه قدیم را از `routes` و `APP_ORIGIN` بردارید.
کد تغییر نمی‌کند؛ فقط این تنظیمات و DNS.

## پشتیبان‌گیری و بازگردانی
- **خودکار:** هر روز ساعت ۳ بامداد (وقت تهران) یک نسخه کامل از اطلاعات داخل خود سرور ذخیره می‌شود؛ ۳۰ نسخه آخر می‌ماند.
- **در برنامه** («ساعت کاری» ← «پشتیبان‌گیری»): زمان آخرین پشتیبان، هشدار اگر بیش از یک روز پشتیبانی گرفته نشده، دکمه دریافت آخرین پشتیبان (فایل JSON)، و «برگرداندن اطلاعات به یک روز قبل».
- **بازگردانی:** نوبت‌ها، اعلان‌ها و ساعت‌های کاری به آن نسخه برمی‌گردند؛ وضعیت فعلی قبلش ذخیره می‌شود (در همان فهرست، «نسخه ذخیره‌شده پیش از یک بازگردانی») پس قابل برگشت است. همه‌چیز در یک تراکنش: اگر مشکلی باشد هیچ تغییری اعمال نمی‌شود. هر دو گوشی فوراً همه‌چیز را از نو می‌خوانند. حساب‌ها، ورودها و سابقه تغییرات (audit_log) دست نمی‌خورند.
- **پیشنهاد:** هفته‌ای یک بار آخرین پشتیبان را دانلود و جای امن نگه دارید (اطلاعات همه بیماران را دارد). هر دانلود و هر بازگردانی در audit_log ثبت می‌شود.

## تضمین‌ها (سمت سرور)
| قانون | پیاده‌سازی |
|---|---|
| هر slot فقط یک نوبت فعال | `UNIQUE INDEX appointments_active_slot_uq ON appointments(start_at) WHERE status <> 'cancelled'` |
| شروع فقط روی :00 یا :30 | `CHECK (start_at % 1800000 = 0)` روی میلی‌ثانیه epoch — آفست تهران (+03:30) مضرب نیم‌ساعت است |
| فرمت موبایل | `CHECK (patient_phone GLOB '09[0-9]…')` |
| ساعت کاری با گام ۳۰ دقیقه | CHECK روی `weekly_schedule` و `date_overrides` |
| یک کاربر برای هر نقش | `role … UNIQUE` |

- Durable Object درخواست‌ها را یکی‌یکی اجرا می‌کند و هر تغییر در یک تراکنش همگام (بدون await) انجام می‌شود: بررسی ساعت کاری، آزاد بودن slot، نسخه، نوشتن، ردیف audit_log و اعلان، همه با هم یا هیچ‌کدام.
- ویرایش با `version`: نسخه قدیمی با `version_conflict` همراه داده فعلی و `updatedBy` رد می‌شود.
- امنیت: رمزها PBKDF2-SHA256، کوکی `__Host-sid` (httpOnly, Secure, SameSite=Lax)، فقط hash توکن ذخیره می‌شود، محدودیت ورود (۵ بار در ۱۵ دقیقه برای هر IP، IPv6 به ازای هر ‎/64؛ و جدا از آدرس، ۱۰ ورود ناموفق در ۱۵ دقیقه برای هر حساب)، فایل پشتیبان بدون hash رمزها، بررسی Origin برای همه درخواست‌های تغییردهنده و کانال لحظه‌ای، همه مسیرهای API به‌طور پیش‌فرض نیازمند ورود، CSP و بقیه هدرهای امنیتی روی همه پاسخ‌ها. لاگ‌ها هیچ اسم یا شماره‌ای ندارند.

## همگام‌سازی لحظه‌ای
- بعد از هر تغییر موفق، سرور از طریق WebSocket (`/api/live`) به همه گوشی‌ها خبر می‌دهد؛ گوشی تغییر را فقط اگر نسخه‌اش جدیدتر باشد اعمال می‌کند.
- بعد از هر اتصال یا اتصال دوباره و هر بار برگشتن اپ به جلو، روز و تنظیمات و اعلان‌ها کامل از سرور خوانده می‌شوند؛ «آنلاین» فقط بعد از این خواندن. هر ۱۰ ثانیه ping؛ بدون جواب در ۵ ثانیه، اتصال از نو.
- نشستی که حذف یا منقضی شده (مثلاً با تغییر رمز) پیش از هر پیام بررسی می‌شود: اتصالش بسته می‌شود و آن گوشی به صفحه ورود می‌رود.
- اعلان‌های منشی در دیتابیس ذخیره می‌شوند و با قطع بودن گوشی گم نمی‌شوند.

## PWA و داده روی گوشی
service worker فقط پوسته برنامه را نگه می‌دارد تا برنامه بدون اینترنت هم باز شود و بگوید وصل نیست. صفحه‌ها همیشه اول از شبکه گرفته می‌شوند. `/api` هرگز از service worker عبور نمی‌کند و ذخیره نمی‌شود: هیچ اطلاعات بیماری روی گوشی نمی‌ماند.

## توسعه و تست
```bash
npm install
cp .dev.vars.example .dev.vars   # تنظیمات محلی
npm run dev                      # صفحه‌ها را می‌سازد و با wrangler dev روی :8787 اجرا می‌کند
npm run typecheck
npm test                         # روی همان runtime کلادفلر (wrangler dev)
npm run test:e2e                 # Chromium در اندازه گوشی ۳۶۰px
```
تست‌ها با `TEST_MODE=1` اجرا می‌شوند که مسیرهای `/api/test/*` (پاک کردن داده) را فعال می‌کند؛ این هرگز در تنظیمات تولید نیست.

## ساختار
```
src/worker/        Worker و Durable Object: API، نشست‌ها، نوبت‌ها، ساعت کاری، اعلان‌ها، کانال لحظه‌ای، پشتیبان
src/shared/        کد مشترک (نرمال‌سازی شماره و اسم، ساعت کاری، تاریخ جلالی، قراردادهای API)
src/app/, src/web/ صفحه‌ها (Next.js، خروجی استاتیک) و منطق سمت گوشی
public/            manifest، آیکن‌ها، service worker
tests/, e2e/       تست‌ها (vitest روی wrangler dev، Playwright)
wrangler.jsonc     تنظیمات Cloudflare (دامنه، نام‌ها، cron پشتیبان)
```
