# سیستم نوبت‌دهی مطب

اپ موبایل (PWA) نوبت‌دهی برای دو کاربر: دکتر و منشی. یک برنامه Node (API + کانال لحظه‌ای + صفحه‌ها) و یک دیتابیس PostgreSQL، روی لیارا.
وضعیت: **فاز ۵ — آماده استقرار.**

> این پوشه را در شاخه `main` مخزن hkk.fyi ادغام نکنید: Cloudflare Pages از `main` منتشر می‌کند و کد این برنامه عمومی می‌شود.

## نصب روی گوشی (دکتر و منشی)
1. در **کروم** اندروید آدرس برنامه (فعلاً `https://clinic.hkk.fyi`) را باز کنید و وارد شوید.
2. «ساعت کاری» (آیکن چرخ‌دنده) ← بخش «نصب روی گوشی» ← دکمه «نصب برنامه روی صفحه اصلی».
   اگر دکمه نبود: منوی ⋮ کروم ← «نصب برنامه» یا «افزودن به صفحه اصلی».
3. از این به بعد برنامه را با آیکن دندان روی صفحه اصلی باز کنید. ورود تا ۱۸۰ روز (با هر بار استفاده تمدید می‌شود) باقی می‌ماند.

صدای اعلان بعد از اولین لمس صفحه فعال می‌شود (محدودیت مرورگر). وقتی برنامه بسته است اعلانی نمی‌رسد.

## استقرار روی لیارا (یک بار)
پیش‌نیاز روی رایانه: Node.js 22، سپس:
```bash
npm install -g @liara/cli
liara login
```

1. **دیتابیس:** در پنل لیارا یک دیتابیس PostgreSQL بسازید (نسخه ۱۶ یا بالاتر). آدرس اتصال **شبکه خصوصی** آن را بردارید (شکل `postgres://USER:PASSWORD@HOST:5432/DB`). برنامه و دیتابیس باید در یک شبکه باشند.
2. **برنامه:** یک برنامه با پلتفرم **Docker** بسازید (در مثال‌ها نامش `clinic` است)، در همان شبکه دیتابیس.
3. **دیسک پشتیبان:** در صفحه برنامه، بخش دیسک‌ها، دیسکی با نام دقیق `backups` بسازید (کوچک‌ترین اندازه کافی است). `liara.json` آن را در `/app/backups` وصل می‌کند.
4. **متغیرهای محیطی** (صفحه برنامه، بخش متغیرها):

   | متغیر | مقدار |
   |---|---|
   | `DATABASE_URL` | آدرس اتصال خصوصی دیتابیس (مرحله ۱) |
   | `APP_ORIGIN` | `https://clinic.hkk.fyi` |
   | `TRUST_PROXY_HOPS` | `1` |
   | `BACKUP_DIR` | `/app/backups` |
   | `SEED_DOCTOR_NAME` / `SEED_SECRETARY_NAME` | نام‌هایی که در برنامه دیده می‌شوند، مثلاً «دکتر کشتکار» و «خانم …» |
   | `SEED_DOCTOR_PASSWORD` / `SEED_SECRETARY_PASSWORD` | رمز هر نفر، حداقل ۸ کاراکتر (فقط برای مرحله ۶) |

   اختیاری: `BACKUP_HOUR` (ساعت پشتیبان روزانه به وقت تهران، پیش‌فرض ۳)، `BACKUP_KEEP` (تعداد پشتیبان‌های نگه‌داشته، پیش‌فرض ۳۰)، `LOG_LEVEL`.
5. **استقرار:** از داخل پوشه `clinic`:
   ```bash
   liara deploy --app clinic
   ```
   لیارا image را از `Dockerfile` می‌سازد. جدول‌های دیتابیس هنگام شروع برنامه خودکار ساخته/به‌روز می‌شوند.
6. **ساخت دو کاربر:** یک شل داخل برنامه باز کنید و دستور را آنجا بزنید:
   ```bash
   liara app shell --app clinic
   node dist/seed.mjs
   exit
   ```
   بعد `SEED_DOCTOR_PASSWORD` و `SEED_SECRETARY_PASSWORD` را از متغیرها **پاک کنید** (رمزها به‌صورت hash در دیتابیس ذخیره شده‌اند).
7. دامنه را وصل کنید (بخش بعد)، بعد `https://clinic.hkk.fyi/healthz` باید `{"ok":true}` بدهد.

### اتصال `clinic.hkk.fyi`
1. پنل لیارا ← برنامه ← دامنه‌ها: `clinic.hkk.fyi` را اضافه کنید. لیارا رکورد DNS لازم را نشان می‌دهد (معمولاً یک CNAME).
2. در Cloudflare (جایی که DNS دامنه hkk.fyi است): رکورد CNAME با نام `clinic` و مقداری که لیارا داد بسازید و **Proxy status را روی DNS only (ابر خاکستری)** بگذارید؛ تا لیارا بتواند گواهی SSL بگیرد و `TRUST_PROXY_HOPS=1` درست بماند. سایت اصلی hkk.fyi دست نمی‌خورد.
3. در لیارا SSL این دامنه را فعال کنید (اگر خودکار فعال نشد) و چند دقیقه صبر کنید.

### انتقال به دامنه ‎.ir (بدون تغییر کد)
1. دامنه جدید (مثلاً `clinic.example.ir`) را در لیارا اضافه کنید، رکورد DNS آن را نزد سرویس DNS دامنه ‎.ir بسازید و SSL را فعال کنید.
2. `APP_ORIGIN=https://clinic.example.ir,https://clinic.hkk.fyi` (دامنه جدید اول). با ذخیره متغیر، برنامه از نو اجرا می‌شود.
3. روی هر دو گوشی: آدرس جدید را باز کنید، دوباره وارد شوید و برنامه را دوباره نصب کنید؛ آیکن قدیمی را حذف کنید. (ورود و برنامه نصب‌شده به آدرس وابسته‌اند.)
4. وقتی هر دو گوشی با آدرس جدید کار کردند: `APP_ORIGIN=https://clinic.example.ir` و دامنه قدیم را از لیارا حذف کنید.

### نسخه جدید
```bash
liara deploy --app clinic
```
گوشی‌ها خودکار دوباره وصل می‌شوند و نسخه جدید با باز کردن بعدی برنامه نمایش داده می‌شود.

### عیب‌یابی
- لاگ‌ها: `liara app logs --app clinic` (لاگ‌ها اسم و شماره بیمار ندارند).
- وضعیت بالای صفحه مدام «در حال اتصال»: `/healthz` را باز کنید؛ اگر خطا داد، دیتابیس یا `DATABASE_URL` را بررسی کنید.
- تغییر رمز یک نفر (مثلاً گوشی گم شده): رمز جدید را در `SEED_SECRETARY_PASSWORD` (یا `SEED_DOCTOR_PASSWORD`) بگذارید، در `liara app shell --app clinic` دستور `node dist/seed.mjs --reset-passwords --only=secretary` (یا `--only=doctor`) را بزنید، بعد متغیر را پاک کنید. همه دستگاه‌های همان نفر حداکثر ظرف ۳۰ ثانیه از حساب خارج می‌شوند؛ نفر دیگر دست نمی‌خورد.

## پشتیبان‌گیری و بازیابی
- **خودکار:** هر روز ساعت ۳ بامداد (وقت تهران) یک پشتیبان کامل (`pg_dump`) روی دیسک `backups` نوشته می‌شود؛ ۳۰ نسخه آخر نگه داشته می‌شوند. اگر برنامه آن ساعت خاموش بود، چند دقیقه بعد از روشن شدن جبران می‌شود.
- **در برنامه:** «ساعت کاری» ← «پشتیبان‌گیری»: زمان آخرین پشتیبان، هشدار اگر بیش از یک روز پشتیبانی گرفته نشده، و دکمه دریافت آخرین پشتیبان. هر دریافت در audit_log ثبت می‌شود.
- **پیشنهاد:** هفته‌ای یک بار آخرین پشتیبان را روی رایانه دانلود و جای امن نگه دارید (فایل اطلاعات همه بیماران را دارد). اگر پلن دیتابیس لیارا پشتیبان‌گیری خودکار دارد، آن را هم روشن کنید.
- **پشتیبان دستی:** در `liara app shell --app clinic` دستور `node dist/backup.mjs`.

**بازیابی** (کل دیتابیس با پشتیبان جایگزین می‌شود):
```bash
liara app shell --app clinic
ls -l /app/backups                                    # فهرست پشتیبان‌ها با تاریخ
node dist/restore.mjs /app/backups/clinic-2026-10-16_0300.dump --yes
exit
liara app restart --app clinic
```
- قبل از جایگزینی، داده فعلی در `pre-restore-….dump` ذخیره می‌شود (حذف خودکار نمی‌شود)؛ پس بازیابی اشتباه هم قابل برگشت است.
- همه‌چیز در یک تراکنش انجام می‌شود: اگر فایل خراب باشد یا وسط کار خطایی رخ دهد، **هیچ تغییری** اعمال نمی‌شود.
- بعد از restart، هر دو گوشی همه‌چیز را از نو می‌خوانند. ورودهایی که بعد از زمان آن پشتیبان انجام شده باشند ممکن است لازم باشد تکرار شوند.
- بازیابی فایلی که روی رایانه است: دسترسی عمومی دیتابیس را موقتاً در لیارا روشن کنید و روی رایانه (با این مخزن و ابزار PostgreSQL نسخه ≥ نسخه سرور): `DATABASE_URL=<آدرس عمومی> npm run restore -- file.dump --yes`؛ بعد دسترسی عمومی را خاموش و برنامه را restart کنید.

## توسعه محلی
پیش‌نیاز: Node.js 22، PostgreSQL 16 (`docker compose up -d`)، و برای پشتیبان‌گیری ابزار `pg_dump`/`pg_restore`/`psql` (یا `PG_BIN` = پوشه آن‌ها).

```bash
cp .env.example .env          # مقادیر را پر کنید
npm install
npm run db:migrate            # ساخت جدول‌ها
npm run db:seed               # ساخت دو کاربر + ساعت کاری پیش‌فرض (فقط آنچه وجود ندارد)
```
تغییر رمزها از روی env: `npm run db:seed -- --reset-passwords` (فقط یک نفر: `--only=doctor` یا `--only=secretary`)

```bash
npm run build                 # صفحه‌ها در out/ و سرور در dist/
npm start                     # سرور: API + صفحه‌ها روی PORT (پیش‌فرض ۳۰۰۰)
npm run backup                # یک پشتیبان در BACKUP_DIR (پیش‌فرض ./backups)
npm run restore -- backups/clinic-….dump --yes
```
ساخت و اجرای image: `docker build -t clinic .` (همان چیزی که لیارا می‌سازد).
برای کار روی ظاهر با بارگذاری خودکار: `npm run dev` (API روی ۳۰۰۰) و در ترمینال دیگر `npm run dev:web` (صفحه‌ها روی ۳۰۰۱؛ در این حالت `APP_ORIGIN=http://localhost:3001`).

## تست
```bash
npm test                      # دیتابیس TEST_DATABASE_URL را پاک و از نو می‌سازد
npm run typecheck
```
نام دیتابیس تست باید با `_test` تمام شود؛ در غیر این صورت تست‌ها اجرا نمی‌شوند.

تست مرورگر (Chromium در اندازه گوشی ۳۶۰px، با دیتابیس جدا `E2E_DATABASE_URL`):
```bash
npm run test:e2e
```
CI (`.github/workflows/clinic.yml`) همه تست‌ها را اجرا می‌کند و image را هم می‌سازد و داخل آن پشتیبان‌گیری و بازیابی را آزمایش می‌کند.

## تضمین‌های سطح دیتابیس
| قانون | پیاده‌سازی |
|---|---|
| هر slot فقط یک نوبت فعال | `UNIQUE INDEX appointments_active_slot_uq ON appointments(start_at) WHERE status <> 'cancelled'` |
| شروع فقط روی :00 یا :30 | `CHECK (extract(epoch from start_at) % 1800 = 0)` — آفست تهران (+03:30) مضرب نیم‌ساعت است، پس این شرط مستقل از timezone است |
| فرمت موبایل | `CHECK (patient_phone ~ '^09[0-9]{9}$')` |
| ساعت کاری با گام ۳۰ دقیقه | CHECK روی `weekly_schedule` و `date_overrides` |
| یک کاربر برای هر نقش | `UNIQUE INDEX users_role_uq` |

ویرایش و لغو با `SELECT … FOR UPDATE` و مقایسه `version` انجام می‌شود؛ نسخه قدیمی با `VersionConflictError` (همراه داده فعلی و `updated_by`) رد می‌شود. هر create/update/cancel در همان transaction یک ردیف `audit_log` با مقدار قبل و بعد می‌نویسد.

خطاهای دیتابیس قبل از خروج از لایه سرویس به `DatabaseError` (فقط کد SQLSTATE) تبدیل می‌شوند، چون خطای خام Drizzle همه پارامترها (اسم و شماره بیمار) را در متن خود دارد. قطع شدن اتصال دیتابیس وسط یک تراکنش پروسه را از کار نمی‌اندازد.

## ساختار
```
drizzle/                 migration های SQL (تولید با npm run db:generate)
src/shared/              کد مشترک کلاینت و سرور (نرمال‌سازی شماره و اسم)
src/server/db/           schema، اتصال، migration runner
src/server/appointments/ ثبت / ویرایش و جابه‌جایی / لغو نوبت
src/server/schedule/     ساعت کاری هفتگی و روزهای خاص
src/app/                 صفحه‌ها (Next.js، خروجی استاتیک)
src/web/                 اجزای صفحه و منطق سمت گوشی (همگام‌سازی روز، اتصال، اعلان‌ها)
src/server/realtime.ts   کانال لحظه‌ای (socket.io، همان مبدأ و همان session)
src/server/notifications/ اعلان تغییرات دکتر برای منشی (در همان تراکنش تغییر)
src/server/backup/       پشتیبان‌گیری روزانه، بازیابی، وضعیت و دانلود
public/                  manifest، آیکن‌ها و service worker
e2e/                     تست‌های مرورگر (Playwright)
scripts/                 migrate، seed، backup، restore، ساخت سرور و service worker
Dockerfile, liara.json   image تولید و تنظیمات لیارا
tests/                   تست‌های constraint، همزمانی و سرویس
```

## همگام‌سازی لحظه‌ای
- بعد از هر تغییر موفق (و فقط بعد از commit)، سرور از طریق socket.io به همه گوشی‌ها خبر می‌دهد؛ گوشی تغییر را فقط اگر نسخه‌اش جدیدتر باشد اعمال می‌کند.
- بعد از هر اتصال یا اتصال دوباره و هر بار برگشتن اپ به جلو، روز و تنظیمات و اعلان‌ها کامل از سرور خوانده می‌شوند؛ وضعیت «آنلاین» فقط بعد از این خواندن نشان داده می‌شود.
- اعلان‌های منشی در دیتابیس ذخیره می‌شوند، پس قطع بودن گوشی چیزی را گم نمی‌کند. صدا (Web Audio، بدون فایل) و لرزش بعد از اولین لمس صفحه فعال می‌شوند (محدودیت مرورگر).
- وقتی اپ بسته است اعلانی نمی‌رسد (بنا به تصمیم: بدون FCM و بدون پیام‌رسان).
- کانال لحظه‌ای فقط WebSocket است؛ پروکسی میزبان باید WebSocket را عبور دهد (Liara پشتیبانی می‌کند).
- هر ۳۰ ثانیه اتصال‌های باز با جدول sessions چک می‌شوند: نشستی که منقضی یا حذف شده (مثلاً با `--reset-passwords`) حداکثر ظرف ۳۰ ثانیه قطع می‌شود و آن گوشی به صفحه ورود می‌رود.
- هنگام خاموش‌شدن (SIGTERM) سرور اول اتصال‌های لحظه‌ای را می‌بندد تا گوشی‌ها فوراً به نمونه جدید وصل شوند؛ اگر بستن بیش از ۱۰ ثانیه طول بکشد، پروسه به‌اجبار خارج می‌شود.

## PWA و داده روی گوشی
- service worker فقط پوسته برنامه (صفحه‌ها و فایل‌های build) را نگه می‌دارد تا برنامه بدون اینترنت هم باز شود و بگوید وصل نیست. صفحه‌ها همیشه اول از شبکه گرفته می‌شوند، پس نسخه جدید فوراً دیده می‌شود.
- `/api` و `/socket.io` هرگز از service worker عبور نمی‌کنند و ذخیره نمی‌شوند: هیچ اطلاعات بیماری روی گوشی ذخیره نمی‌شود.

## نکات امنیتی و نگه‌داری
- هیچ وابستگی بیرونی در زمان اجرا نیست: فونت، آیکن و همه فایل‌ها از خود برنامه می‌آیند.
- اگر دیتابیس مقداری را با CHECK رد کند، خود PostgreSQL ممکن است آن ردیف را در لاگ خودش بنویسد. برنامه همه ورودی‌ها را قبل از نوشتن بررسی می‌کند، پس این در عمل رخ نمی‌دهد؛ لاگ دیتابیس لیارا هم فقط در دسترس صاحب حساب است.
- پشتیبان‌ها شامل اسم و شماره بیماران‌اند: روی دیسک خصوصی برنامه می‌مانند و فقط کاربر واردشده می‌تواند آخرین را دانلود کند (ثبت در audit_log).
